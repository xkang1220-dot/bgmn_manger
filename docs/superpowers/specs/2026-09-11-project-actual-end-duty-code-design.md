# 项目实际结束时间、参与人职责与编号自动生成

日期：2026-09-11  
状态：待实现  
关联：项目参与人任务可见性（2026-09-11）

## 目标

1. 项目结束时间拆成「预计结束时间」与「实际结束时间」。  
2. 项目参与人必填「职责」标识（短文本，非权限）。  
3. 任务参与人 / 移交对象仅能从「项目负责人 ∪ 项目参与人」中选择。  
4. 创建项目时自动生成编号：公司名拼音首字母 + `-` + 三位序号；编号不可改。

## 非目标

- 不自动根据状态写入实际结束时间。  
- 不校验实际结束 ≥ 预计结束。  
- 不为职责做字典/枚举。  
- 不拆分财务分成表；职责复用 `pm_project_member.layer`。  
- 不新增公司英文简称字段。

## 数据

| 项 | 处理 |
|----|------|
| `pm_project.end_date` | 语义改为「预计结束时间」；字段名不变，API 仍为 `endDate` |
| `pm_project.actual_end_date` | 新增 `DATE NULL`，API `actualEndDate`，仅手动 |
| `pm_project.code` | 创建时后端生成；更新时忽略入参 |
| `pm_project_member.layer` | 存职责文案，创建/编辑项目时必填，≤ 64 字 |
| `pm_project_member.percent` | 同步参与人时继续保留已有分成 |

升级脚本：`sql/upgrade_project_actual_end_duty_code.sql`（本地可执行）。

## 编号规则

- 前缀：公司部门名称转拼音首字母大写（仅保留 A–Z；无字母时用 `PRJ`）。  
  例：「西游公司」→ `XYGS`。  
- 序号：该公司下已有 `code` 匹配 `{前缀}-数字` 的最大序号 + 1，三位补零（`001`…）；超过 999 继续加长。  
- 格式：`{前缀}-{序号}`，如 `XYGS-001`。  
- 生成时机：直连创建、以及 `PROJECT_CREATE` 审批生效；忽略前端/payload 中的 `code`。  
- 编辑项目：编号只读，后端不更新 `code`。

## 写操作规则

### 项目

- 参与人：每人必须有非空职责（`layer` trim 后非空）。  
- `syncCollaborationMembers`：写入用户填写的 `layer`；保留已有 `percent` / 财务 `remark`。  
- 空参与人列表：允许（清空成员）；有成员则职责必填。

### 任务

- 创建/更新任务的 `participantIds`、移交目标用户：必须 ⊆（项目 `ownerId` ∪ 该项目 `pm_project_member.user_id`）。  
- 后端强校验；前端下拉仅展示上述候选。  
- 历史脏数据：详情仍可展示；保存时不允许继续写入范围外用户（须先从参与人中移除或补进项目成员）。

## 前端

- 项目表单：`结束日期` → `预计结束时间`；增加 `实际结束时间`；编号只读（创建时可显示「保存后自动生成」或预览接口结果，以只读展示为准）。  
- 项目参与人：由多选改为「人员 + 职责」列表；保存前校验职责。  
- 详情/列表：参与人展示为 `昵称（职责）`；日期区展示预计/实际。  
- 任务详情/看板创建编辑、移交：候选人来自项目负责人 + 项目成员（含职责展示可选）。

## 验收

1. 新建项目不选手填编号，生效后为 `拼音前缀-001` 形态且不可改。  
2. 同公司第二个项目序号递增。  
3. 参与人未填职责无法保存。  
4. 任务参与人下拉不含公司内非项目成员；强行传 ID 后端拒绝。  
5. 负责人不在成员表时，任务仍可选负责人。  
6. 预计/实际结束均可空、可独立填写。

## 风险

- 中文转拼音依赖库或自研映射；需处理多音字可接受偏差（以常见库结果为准）。  
- 公司改名后旧编号前缀不回溯；新项目用新名称前缀。  
- 财务侧若曾用 `layer` 作分层文案，会被职责覆盖；当前项目侧已统一写「参与」，可接受。
